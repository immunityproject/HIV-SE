# HIV-SE

These data files were produced in conjunction with the code in the [pySE](https://github.com/immunityproject/pySE) repository. 

This is an extremely large dataset.


# Structure
The HIV-SE repository contains sub-directories for each protein in HIV, with sub-sub-directories for each FoldX job related to that protein. These job directories are named with a Globally Unique ID (GUID), and each represents one mutation of one site on one protein.

Each job directory contains these files:
*   individual_list.txt – informs FoldX of the site and mutation to perform on each chain in the protein. It consists of a single row of comma-delimited mutation strings. Each mutation string has the one letter code representing the WT amino acid to replace, followed by one character for the chain code,followed by a numerical site index relative to that chain, followed by a final letter representing the one letter amino acid code for the mutation to perform. This file is generated by generate buildmodel.py.
*  list.txt – informs FoldX of the protein’s PDB filename. The PDB files are not located in the job directories but in the working directory of the FoldX application. They may also be found in the source code repository in the pdbs/ folder.
*  BuildModel_*.fxout – textual summary output from FoldX.
*  Raw_BuildModel_*.fxout – a tab-delimited table of all the component energies for each folding run. Since we repeat each folding calculation 5 times,there will be five rows in this table for each mutation site, plus 5 rows for the WT energy. This file has the most detailed breakout of the FoldX energy results.
*  Dif\_BuildModel\_*.fxout – a tab-delimited table of the energy differences for each mutation versus the WT. Since we repeat each folding run 5 times, there will be five rows in this table.
*  Average_BuildModel_*.fxout – a tab-delimited table of the average energy difference across all runs for a given mutation versus the WT. This file has a single row which we use as the mutation’s base ∆G, the final output of the FoldX calculation which is used in the amino acid site’s array of mutation energies.
* \*\_1\_\*.pdb – these are standard PDB files representing the final folded (minimum energy) state of the mutation. Since we run the folding calculation 5times, there are five of these files, one for each run.
*  WT_\*\_1\_\*.pdb – these are standard PDB files representing the final folded(minimum energy) state of the unmutated protein. Since we run the folding calculation 5 times, there are five of these files, one for each run. These files will be slightly different than the input PDB due to randomness in the Monte Carlo folding process. FoldX re-folds the original input PDB for every mutation run,and these files are the result.
*  PdbList\_BuildModel\_\*\_.fxout – a list of all the PDB output files generatedby the folding process.
*  lockfile – this file is generated by scan foldx jobs.py when an instance in the compute cluster begins working on the job directory. It contains the hostname of the compute cluster instance which performed the folding.
*  completed – this file is generated by scan foldx jobs.py when an instance in the compute cluster has completed working on the job directory.
